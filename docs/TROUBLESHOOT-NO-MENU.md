# Почему приложение не появилось в Menu → Applications

Разбор по фактам с реального DS-24 II (прошивка 6.06) и официального
`JETI DCDS_Lua_API_1.7.pdf`, который лежит в корне карты передатчика.

## Что видел пользователь

`F3X Courses` появился **только в разделе датчиков** (список телеметрических окон),
а в `Menu → Applications` его нет.

## Что это значит

Это не «одно и то же приложение частично загрузилось». Это два разных механизма:

- **`system.registerTelemetry(...)`** создаёт телеметрическое окно, и **это окно
  сохраняется в файле модели**. Поэтому оно видно даже тогда, когда приложение
  в меню не попало и, возможно, вообще не запускалось сейчас.
- **`system.registerForm(...)`** создаёт пункт в меню. Он живёт только до
  перезагрузки — в модели не сохраняется. Нет формы → приложения в меню нет.

Отсюда вывод: телеметрийное окно в данном случае **ничего не доказывает**.
Оно могло остаться в модели с прошлого запуска.

## Три независимые причины, каждая даёт этот же симптом

### 1. Приложение не активировано для модели (главная)

В API 1.7, раздел «Loading the applications»:

> The DC/DS-24 offers a simple overview of installed and active applications.
> See the menu **Applications – User Applications**. […] Using the **F(3) “Plus”** button
> you can activate additional Lua applications (**up to 10 can be active per model**
> at the same time).

То есть файл в `Apps/` — это ещё не активное приложение. Его надо **включить для
модели** через `F3` («Plus»). А на карте лежит **17** файлов `.lua`/`.lc`:

```
BURANF3B.lua  BattMon.lc  BattVolt.lc  DEVICE26.lua  Display.lc  Horizon.lc
Horizon_24.lc  MainLow.lc  PIKEF3F2.lua  PIKEX202.lc  ...  f3f_21.lc  f3xc.lua
```

Лимит — 10 активных на модель. У нас 17 кандидатов, и `f3xc.lua` почти наверняка
не попал в активные.

### 2. `registerForm` без `printFunction`

Сигнатура из API 1.7:

```
system.registerForm (<formNo>, <parentMenuID>, <label>,
                     <initFunction>, <keyPressFunction>,
                     <printFunction>, <closeFunction>)
```

В версии 0.1.1 мы передавали только первые пять аргументов. `printFunction` —
функция, которая рисует содержимое формы; без неё нечего показывать, и форма
не регистрируется. Все работающие приложения на этой карте передают рисующую
функцию: `system.registerForm(1, MENU_APPS, "...", nil, key, draw)`.

### 3. `initFunction` ссылался на локальную переменную, объявленную ниже

В промежуточной правке обёртка `initFormGuarded` ссылалась на `initForm`,
объявленный **ниже** неё. В Lua это `nil`, и `pcall(initForm, ...)` падал
с «attempt to call a nil value». Ошибка проглатывалась `pcall`, регистрация
отменялась — приложение оставалось только с телеметрией.

## Что сделано в 0.1.2

- `printFunction` передаётся в `registerForm` всегда (`printForm` рисует сводку
  через `lcd`, если виджеты не построились).
- Порядок объявлений исправлен: `initForm` объявлен **до** обёртки.
- Если `initForm` всё же упадёт, ошибка ловится, показывается на самой форме
  и пишется в журнал; регистрация формы при этом не отменяется.
- Регистрация идёт по цепочке меню: `MENU_APPS` → `MENU_ADVANCED` → `MENU_MAIN`,
  и если прошивка не приняла форму с виджетами, повторяется попытка
  в режиме «только канвас» (без `initFunction`).
- Каждый шаг `init` пишется в `Apps/f3xc/lastrun.txt` (если не удалось —
  в `lastrun.txt` в корне карты).

## Что добавлено в 0.1.3

Посмотрел, как устроены приложения, которые на этой карте **реально** открываются
(`BURANF3B.lua`, `PIKEF3F2.lua`, `PIKEX202.lua`, `DEVICE26.lua`, `f3f_21.lc`).
Все они регистрируют форму так:

```lua
system.registerForm(1, MENU_APPS, "имя", nil, key, draw)
```

Виджетов (`form.addRow`, `form.addLabel`, …) нет **ни в одном**. Значит, на этом
передатчике надёжный путь — рисовать страницу самому через `lcd`.

Поэтому резервный режим стал полноценным:

- страница курсов: `F1` — новый курс с позиции GPS, `F2` — удалить, `F3` — сделать
  активным, `F4` — перечитать с карты, `F5` — страница датчиков; выбор курса энкодером;
- страница датчиков: показывает, что именно привязано (имя и param), сама запускает
  авто-подбор (`GPSLog3`), `F4` — перепривязать, `F1`/`ESC` — назад;
- маршрутизация клавиш адаптивная: виджеты построились — работают виджеты,
  не построились — работает канвас;
- `printForm` в виджетном режиме молчит, чтобы текст не ложился поверх формы.

## Как проверить

1. `Menu → Applications → User Applications` (не просто `Applications`).
2. Найти в списке `F3X Courses`.
3. Если его нет в активных — выделить и нажать **F3** (Plus), чтобы добавить.
4. Если список уже полон (10 активных) — убрать **F4** (Delete) одно ненужное
   для этой модели; файл на карте при этом не удаляется.
5. Перезагрузить передатчик, зайти в `Menu → Applications → F3X Courses`.

После этого забрать журнал с карты: `Apps/f3xc/lastrun.txt`. В нём будет
видно, какое меню приняло форму и что ответила прошивка:

```
init F3X Courses 0.1.3  lua Lua 5.3
registerForm MENU_APPS(11) -> ok=true ret=1
registerTelemetry -> ok=true ret=1
ready
```

Если там `FORM NOT REGISTERED` или `initForm(1) error: ...` — причина названа
дословно, гадать не нужно.
