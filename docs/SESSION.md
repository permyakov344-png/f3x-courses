# Контекст для продолжения работы

Этот файл — «точка входа» для новой сессии. Прочитав его, можно продолжить с того же места,
не восстанавливая переписку.

## Задача

Мини-GPS-сенсор и приложение для **JETI DS-24 II**, чтобы пищать на базовой линии F3B (150 м)
на тренировках. Сенсор у пользователя уже есть и работает — с него летали. Осталась
**только программа**: F3F Tool V2 работает, но его настройка непонятна.

## Что уже решено

| Вопрос | Решение |
|---|---|
| Передатчик | JETI DS-24 II, цветной экран, Gen-2, Lua API 5.x |
| Сенсор | `GPSLog3` (JETI GPS Logger 3), ID `823632641`. Lat=3, Lon=4, Speed=5 (км/ч), Dir=9 — подтверждено по карте |

| Дальности | До 500 м по горизонтали и 500 м по высоте |

## Почему F3F Tool не устраивает (для истории)

1. Два отдельных меню — «Configuration» и «Course Setup», связь между ними не очевидна.
2. Список сенсоров фильтруется по `type == 9`; если GPS публикует иначе — список пуст.
3. Для F3B надо сканировать 2 точки **параллельно линии A**, а не базы A/B; потом код делает `bearing - 90°`.
4. Стартовая точка — это центр курса, а не база A (`gps.getDestination(start, dist/2, bearing)`).
5. Ручной ввод угла: для F3F это направление ветра (+90°), для F3B — направление полёта.
6. Курс хранится глобально в `slopeData.jsn`, а конфиг — в `pSave` на модель.
7. Одна кнопка на три функции (клик / двойной / удержание), без индикации режима.
8. Константы компенсации задержки (`58/62/6`) захардкожены, в UI их нет.

### Почему не появлялось в Menu → Applications (24.11.2026)

Окно телеметрии сохраняется **в файле модели**, поэтому оно было видно, даже когда
приложение в меню не попало. Форма же в модели не хранится. Причины разобраны
в `TROUBLESHOOT-NO-MENU.md`:

1. **Главная:** приложения на DS-24 II включаются вручную —
   `Menu → Applications → User Applications`, кнопка **F3 (Plus)**; активных
   на модель максимум **10**, а на карте **17** файлов `.lua`/`.lc`.
2. `registerForm` вызывался без `printFunction` — без неё форма не регистрируется.
3. В промежуточной правке обёртка `initFormGuarded` ссылалась на `initForm`,
   объявленный ниже (`nil`), ошибка проглатывалась `pcall`.

### Режим «только канвас» (0.1.3)

Все приложения, которые на этой карте реально открываются, регистрируют форму как
`registerForm(1, MENU_APPS, "имя", nil, key, draw)` — без виджетов. Поэтому
резервный режим доведён до полноценного: две страницы, навигация энкодером,
создание/удаление/активация курса, авто-привязка датчиков. Приложение работает
в любом случае: построились виджеты — виджеты, нет — канвас.

## Технические заметки

- Приложение — **один файл** `Apps/F3x Courses.lua`, без `require`, чтобы не зависеть от путей модулей.
- Все обращения к `io`/`gps`/`system.getSensorByID` обёрнуты в `pcall` — приложение не должно падать
  при потере телеметрии.
- `system.pSave` — **на модель**, поэтому привязка сенсоров своя у каждой модели. Курсы — глобальные.
- Формы: одна регистрация `system.registerForm(1, MENU_APPS, ...)` с внутренней навигацией
  через `form.reinit(1|2)` и `form.addLink`. Отдельный `registerForm(2, ...)` не нужен.
- Телеметрийное окно: `system.registerTelemetry(1, name, 3, print, key)` — `3` = весь экран,
  и только такой размер получает нажатия клавиш. `setTelemetryButton` работает на
  DS-24 II с прошивки V6.05 и только после регистрации окна — поэтому в `pcall`.
- Синтаксис проверен парсером Lua 5.3 (`luaparse`), логика — тестами на заглушках.
  Версия 0.1.5 на железе ещё не проверялась. Отдельный риск: кириллица в шрифте прошивки —
  в таблице символов API 1.7 её нет, проверять на передатчике (п. 7 чек-листа).
- Установка: `Apps/F3x Courses.lua` + каталог `Apps/f3xc/`.

## Разбор сенсоров (сделан, решений не меняет)

Подробности — `SENSOR-NOTES.md`. Коротко:

- RCGPS-F3x / Slim (Cassini, автор Axel Barnitzke) — хорошее железо, но для Jeti он сам
  ссылается на F3F-Tool. Нашей задачи (понятный интерфейс на DS-24 II) покупка не решает.
- «Работает быстрее» упирается в JETI EX: 9600 бод, 9N2, пауза ≥ 20 мс → потолок ~10 Гц
  на устройство независимо от сенсора. Выигрыш — в плотности выборок и устойчивости
  к перегрузкам, а не «в разы».
- Питание RCGPS 5.5–8.4 В: на борту 4.8–5 В работать не будет.
- Ценная находка: у Axel Barnitzke (`course.lua`, MIT) и у F3F-Tool компенсация задержки
  сходится к `offset ≈ k·v`, k ≈ 0.06–0.1 с. Значит в шаге D ползунок делать
  **в секундах**, не в процентах.
