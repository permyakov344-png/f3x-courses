# Тесты

Тестовый фреймворк не нужен: тесты — это отдельные Lua-скрипты, которые проверяют
логику приложения на заглушках JETI API. Смысл в том, чтобы ловить ошибки до заливки
на передатчик, потому что отладка на DS-24 медленная.

## Чем запускать

Нужен любой Lua 5.3. Если `lua` в системе нет, работает `fengari` (Lua на JS):

```bash
# разово
cd /tmp && npm install fengari-node-cli
# запуск из корня репозитория
/tmp/node_modules/.bin/fengari tools/test-app.lua
/tmp/node_modules/.bin/fengari tools/test-bind.lua
```

Если Lua 5.3 установлен (`brew install lua`):

```bash
lua5.3 tools/test-app.lua
lua5.3 tools/test-bind.lua
```

## Что проверяется

- `tools/test-app.lua` — **прогоняет настоящее `Apps/f3xc.lua`** на заглушках JETI API.
  Ловит ровно тот класс ошибок, из-за которого приложение пропадает из меню:
  - `init()` не падает;
  - `system.registerForm` получает **функцию** init и **функцию** print
    (если init — `nil`, форма не регистрируется, и приложение остаётся только
    в списке телеметрии);
  - `initForm(1)` и `initForm(2)` строят виджеты без ошибок;
  - обработчик клавиш переживает любую клавишу, включая неизвестные коды;
  - `printForm` рисует без ошибок;
  - строгая прошивка (init обязателен, print обязателен) всё равно регистрирует форму;
  - падение виджета ловится: форма остаётся, ошибка уходит на экран и в журнал;
  - **прошивка принимает только »nil init + key + print»** (так устроены все рабочие
    приложения на этой карте): форма всё равно регистрируется, журнал пишет
    `canvas-only`, канвас-страница рисует 9–10 строк, а обработчик клавиш и переход
    на страницу датчиков не падают ни на одной клавише;
  - в `lastrun.txt` действительно записано, что форма зарегистрирована;
  - **сценарий 5 — окно телеметрии**: `system.registerTelemetry` вызывается с
    размером `3` (весь экран) и получает `printFunction` **и** `keyPressedFunction`
    (клавиши работают только на полном экране), выставляются 5 кнопок
    `setTelemetryButton`; окно рисуется на 800×480, 320×240, 320×120 и 200×90;
    обработчик клавиш переживает `F1..F5`, `Enter`, `Esc`, стрелки и мусорные коды;
    курс с обеими базами попадает в кадр (`имя курса`, `ЛИНИЯ A-B`, `ДАТЧИКИ`).
- `tools/test-bind.lua` — профиль `GPSLog3`. Заглушка `system.getSensors()` отдаёт
  ровно те строки, что найдены на передатчике (ID `823632641`: Latitude 3, Longitude 4,
  Speed 5, Flight Dir. 9). Проверяется:
  привязка по групповой строке `GPSLog3`; привязка без групповой строки (через `Latitude`);
  что посторонняя телеметрия (`UniS-E`) ничего не привязывает; что повторный вызов
  ничего не перезаписывает.
- `luaparse` (синтаксис): `npx luaparse Apps/f3xc.lua` — ошибок быть не должно.

## Просмотр окна без передатчика

```bash
/tmp/node_modules/.bin/fengari tools/preview-telemetry.lua > /tmp/tel.svg
```

Скрипт поднимает `Apps/f3xc.lua` на заглушках с придуманным курсом и GPS-фиксом и
рисует полноэкранное окно телеметрии в SVG: видно, как легли блоки, не наезжает ли
текст, влезает ли подсказка. Готовые картинки — `docs/screens/f3xc-0.1.5-*.svg`.

Ширина текста считается в **символах UTF-8**, а не в байтах, и кириллица получает
поправку на большую ширину — иначе русские строки в превью выглядели бы вдвое
длиннее, чем на экране.

## Что тесты не заменяют

`form`, `lcd`, `gps` на настоящем передатчике ведут себя иначе, чем заглушки.
После каждого шага — `docs/TEST-CHECKLIST.md`.

## Выгрузка в GitHub

```bash
bash tools/sync-github.sh              # сообщение придумается само
bash tools/sync-github.sh "текст"      # своё сообщение
```

`git add -A` (картинки из `docs/screens/` тоже), коммит, `pull --rebase`, `push`,
и печатает, что именно ушло. Правило проекта: изменения выгружаются сразу после
проверки на передатчике, вместе со скриншотом, чтобы версию можно было вернуть.

Скриншоты кладутся в `docs/screens/` и называются по версии:
`f3xc-<версия>-<что>.jpg`. Полное разрешение не нужно — 1400 px по длинной
стороне достаточно:

```bash
sips -s format jpeg -s formatOptions 82 -Z 1400 фото.HEIC --out docs/screens/f3xc-0.1.5-courses.jpg
```
