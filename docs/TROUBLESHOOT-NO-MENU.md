# Почему приложение не появилось в Menu → Applications

Разбор по фактам с реального DS-24 II (прошивка 6.06) и официального
`JETI DCDS_Lua_API_1.7.pdf`, который лежит в корне карты передатчика.

**Итог: файл `Apps/f3xc.lua` был исправен всё это время.** Передатчик его видел,
но приложение не было **добавлено в активные для модели**. Подробности ниже.

## Что видел пользователь

`F3X Courses` появился **только в разделе датчиков** (список телеметрических окон),
а в `Menu → Applications` его нет.

## Как это устроено на самом деле

Это два разных механизма:

- **`system.registerTelemetry(...)`** создаёт телеметрическое окно, и **это окно
  сохраняется в файле модели**. Поэтому оно видно даже тогда, когда приложение
  в меню не попало и вообще сейчас не запускалось.
- **`system.registerForm(...)`** создаёт пункт в меню. Он живёт только до
  перезагрузки — в модели не сохраняется. Нет формы → приложения в меню нет.

Отсюда вывод: телеметрийное окно в данном случае **ничего не доказывает**.
Оно осталось в модели с прошлого запуска.

## Настоящая причина

В API 1.7, раздел «Loading the applications»:

> The DC/DS-24 offers a simple overview of installed and active applications.
> See the menu **Applications – User Applications**. […] Using the **F(3) “Plus”** button
> you can activate additional Lua applications (**up to 10 can be active per model**
> at the same time).

Главное, что было понято не сразу: **F3 (Plus) открывает список *доступных*
файлов, а не активных приложений.** Само открытие списка ничего не добавляет.
В этом списке надо:

1. выделить строку `f3xc.lua` крутилкой;
2. нажать **саму крутилку** (Enter / кнопка 3D) — это и есть «добавить».

Только после этого файл становится активным приложением модели, появляется в
`Menu → Applications` и запускается. Именно этого шага не хватало: файлы в списке
были видны (`testba`, `f3xc.lua`, `f3xmini`, `f3f_21`), но ни один не был добавлен.

Лимит — 10 активных на модель. Если список полон, в списке активных выделить
ненужное и нажать **F4 (Delete)**: приложение отключается для модели, файл на
карте остаётся.

## Точный признак, что приложение не запускалось

`init` пишет журнал **первой же строкой**. Значит:

- нет `Apps/f3xc/lastrun.txt` → прошивка файл **не запускала** (не активирован);
- файл есть → приложение запустилось, и в нём дословно видно, что произошло.

Всё это время `lastrun.txt` отсутствовал — это и был ответ. Не «не компилировала»,
а не запускала.

## Что было исправлено в коде по пути (0.1.2)

Две настоящие ошибки, каждая могла дать тот же симптом. Они были исправлены
до запуска и не помешали, но и не были причиной:

- `system.registerForm` вызывался **без `printFunction`**. Сигнатура API 1.7:

  ```
  system.registerForm (<formNo>, <parentMenuID>, <label>,
                       <initFunction>, <keyPressFunction>,
                       <printFunction>, <closeFunction>)
  ```

  Теперь `printFunction` передаётся всегда.

- `initFormGuarded` ссылался на `initForm`, объявленный **ниже** него. В Lua это
  `nil`, `pcall` проглатывал ошибку, регистрация отменялась. Порядок объявлений
  исправлен.

Плюс добавлена страховка: регистрация идёт по цепочке `MENU_APPS` → `MENU_ADVANCED`
→ `MENU_MAIN`, при отказе формы с виджетами повторяется попытка «только канвас»
(без `initFunction`), а падение `initForm` ловится и показывается на экране.

## Что добавлено в 0.1.3

Посмотрел, как устроены приложения, которые на этой карте открываются
(`BURANF3B.lua`, `PIKEF3F2.lua`, `PIKEX202.lua`, `DEVICE26.lua`, `f3f_21.lc`):
все регистрируют форму как `system.registerForm(1, MENU_APPS, "имя", nil, key, draw)`,
без виджетов, рисуя страницу через `lcd`.

Поэтому резервный режим стал полноценным:

- страница курсов: `F1` — новый курс, `F2` — удалить, `F3` — сделать активным,
  `F4` — перечитать с карты, `F5` — датчики; выбор курса энкодером;
- страница датчиков: показывает, что привязано (имя и param), сама запускает
  авто-подбор `GPSLog3`, `F4` — перепривязать, `F1`/`ESC` — назад;
- маршрутизация клавиш адаптивная: виджеты построились — работают виджеты,
  не построились — работает канвас;
- `printForm` в виджетном режиме молчит, чтобы текст не ложился поверх формы.

## Проверено на передатчике (24.11.2026)

Приложение запустилось, виджеты построились. Журнал с карты:

```
init F3X Courses 0.1.3  lua Lua 5.3
registerForm MENU_APPS(5) -> ok=true ret=1
registerTelemetry -> ok=true ret=1
ready
```

## Если понадобится повторить на чистой карте

1. Скопировать `Apps/f3xc.lua` в `Apps/` на карте передатчика
   (`bash tools/install-to-tx.sh`).
2. Вставить карту в передатчик, включить.
3. `Menu → Applications` → **F3 (Plus)** → выделить `f3xc.lua` → **нажать крутилку**.
4. `Menu → Applications` → `F3X Courses` → крутилка.
5. Забрать `Apps/f3xc/lastrun.txt` — там будет `ready`, если всё хорошо.

Для быстрой проверки самого загрузчика есть `tools/F3XMINI.lua`: минимальное
приложение на 1.5 КБ, одна страница `lcd`. Если оно в списке есть, а наше нет —
дело в файле; если нет ни одного — дело в карте или слоте.
