## B. Мастер настройки по двум базам

Цель — убрать главную ловушку F3F Tool: там нужно сканировать две точки **вдоль** линии A,
а потом код поворачивает на 90°. В F3B базы A и B известны физически, поэтому сканируем
прямо их.

- [ ] Экран мастера: `1. Set A` → `2. Set B`
- [ ] Живой показ: сколько метров прошёл от A, сколько осталось до 150
- [ ] Проверка результата: `A→B = 149.3 m`, отклонение от номинала, курс в градусах
- [ ] Предупреждение, если дистанция вне допуска или fix плохой
- [ ] Сохранение `aLat/aLon/bLat/bLon/brg/dist` в курс
- [ ] Кнопка `Rescan` и ручной ввод курса числом (если пройти 150 м невозможно)

**Проверка на железе:** проходим 150 м по рулетке/шагам — приложение показывает ~150 м.

## D. Настройка задержки и разбор полёта

- [ ] Ползунок компенсации задержки вместо констант `58/62/6` из F3F Tool.
      **Решено:** ползунок в **секундах** (0.00–0.30), а не в процентах — обе
      известные реализации (F3F Tool и `gpsF3XTracker`) сходятся к `offset ≈ k·v`,
      k ≈ 0.06–0.1 с. См. `SENSOR-NOTES.md`, п. 5.
- [ ] Экран диагностики: `along/across`, время с последней посылки, частота обновления GPS

## Ограничения, о которых помним

- Телеметрия JETI EX — 9600 бод, реальная задержка 0.3–0.5 с. На 70 м/с это 21–35 м.
  Компенсация обязательна, иначе speed-результат будет завышен.
- Приложение не должно зависать при потере телеметрии.
- Курсы хранятся глобально (как в F3F Tool), но активный индекс — тоже в файле.
  Привязка сенсоров — через `system.pSave`, то есть **на модель**.
